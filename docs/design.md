# シュート軌道解析アプリ（iPad・Safari）設計 2026/11/26

NOAH（リング上のセンサーでシュートの入射角などを測り、声で知らせる装置）のような軌道解析を、iPadのカメラとSafariだけで行うWebアプリ。
（原本：claude.aiプロジェクト「BasketBall」の `claude/シュート軌道解析アプリ_設計_20261126.md`）

## 1. なぜ作るか（前橋さんの発言）
- 1人で打つシュートの軌道を測り、前橋さんが子どもへのアドバイスに使う。子どもが自分で直すのは難しいので、見るのは前橋さん
- その場で結果が分かる形がよい（リアルタイム）
- 後で分析できるように、1本ごとのデータと動画を残したい
- 動画は後で消せるようにし、データ（数字）だけをPCに移せるようにしたい
- FalconはSDカードをPCに移す作業が要るので、iPadでやりたい
- Macはない。Safari（Webアプリ）で作る

## 2. ゴール・やらないこと・失敗とみなすこと
**ゴール**
- iPadを三脚でゴールの横に固定し、アプリを開いて打ち始めれば、1本ごとに声と画面で結果が出る
- 1本ごとに数字と短い動画（軌道の線入り）がiPadにたまる
- 数字だけをCSVで書き出してPCに移せる。動画は後で消せる（数字は残る）

**やらないこと（今回）**
- 左右のずれの測定（真横の1台では測れない）
- 試合動画への対応（1人シュートだけ）
- 子どもが自分で見て直すための画面・ゲーム要素
- 動画の自動アップロード、サイトへの公開
- 子ども向けの「理想の角度」を決めること（基準が見つかっていない）

**失敗とみなすこと**
- 間違った数字を、正しそうに読み上げる（測れなかったときは「はかれなかった」と言う）
- 子どもの映像が、前橋さんが操作しないのにiPadの外に出る
- 毎回の準備が面倒で使わなくなる（目安：三脚を立ててから打ち始めるまで1分以内）
- データが知らないうちに消える

## 3. 前提・制約
- 【事実】Macなし。iPadのSafariで動くWebアプリにする（前橋さん 11/26）
- 【事実】撮影はT4三脚に付けたiPad。T4は最大4m・最低1.37m、1/4インチネジでスマートフォンなども付けられる（XbotGo公式 T4三脚ページ）
- 【事実】撮影場所は主に自宅前のゴール。過去の練習動画は横から固定で撮っており、背景は空（練習動画シュート集_手順 rev1）
- 【事実】カメラ位置は毎回変わる可能性がある（前橋さん 11/20）
- 【事実】打つのは子ども（虎旺・和奏など）。1人ずつ打つ
- 【推論】カメラはシュートの真横に置く。真横からなら放物線がそのまま映り、入射角・最高点・リングのどこを通ったか（手前／奥）が出せるため
- 【推論】Safariでカメラを使うには、https のアドレスで配信する必要がある

## 4. 考えた案
| 案 | 中身 | よい点 | 弱い点 | 結果 |
|---|---|---|---|---|
| A | iPadだけで完結。その場で解析し、1本ごとの短い動画と数字をiPadに保存。ときどき書き出す | 機材1台、移す作業が少ない、短い動画なので軽い | Safariの性能・機能の制約を試作で確かめる必要 | **採用**（前橋さん 11/26） |
| B | iPadは数字だけ。練習まるごとの動画を後でPCに移して解析 | iPadの負担が軽い、精度を上げやすい | 大きな動画を毎回PCに移す手間が残る | 不採用 |
| C | iPadの映像をミニPCに送ってその場で解析 | 計算力が大きい | 仕組みが複雑、家のネットワーク設定が必要 | 不採用 |
| （前段） | 本格的なiPadアプリ（Swift Playgrounds／Expo） | カメラの性能を引き出せる | Claude Codeと相性が悪い／年99ドルの登録が必要 | Safari版で足りなければ再検討 |

## 5. 使い方の流れ
```
① iPadを三脚でゴールの真横に置き、アプリを開く
② 打つ人を選ぶ（虎旺・和奏・咲心・追加）
③ リングの位置合わせ：自動でリングを見つけて枠を出す → 合っていれば「OK」。ずれていればリングの左端・右端をタップ
④ 打ち始める。1本ごとに声で「よんじゅうさんど、てまえ」、画面に数字と軌道の線
⑤ 終わったら「おわり」。その日のまとめが出る
⑥ 必要なときに「データを書き出す」→ 共有メニューからPCへ（ファイル・OneDrive・LINEなど）
⑦ 動画が不要になったら消す（数字は残る）
```

## 6. 画面
**撮影中（横向き）**
```
┌──────────────────────────────────┐
│  カメラ映像＋リングの枠＋直前の軌道（線）            │
│                                          │
│  にゅうしゃかく 43°  さいこうてん 3.4m  てまえ  ○  │
│  きょう：12本 7本入った  へいきん 41°   [おわり]   │
└──────────────────────────────────┘
```
- 文字は前橋さんが少し離れて見ても読める大きさにする
- 測れなかったシュートは「はかれなかった」と表示し、平均に入れない

**記録の一覧**
- 日付→回（セッション）→1本ずつ。1本を押すと動画を再生（スロー・コマ送り）
- 入った／外れたの自動判定を、タップで直せる
- 消す：1本ずつ／回ごと／「書き出し済みの動画をまとめて消す」。消すのは動画だけで、数字は残る

## 7. 測る項目（1本ごと）
| 項目 | 中身 |
|---|---|
| 日時・打った人・回の番号・何本目 | |
| 入った／外れた | 自動判定。手で直した場合はその印も残す |
| 入射角 | リングの高さを通るときの、ボールの進む向きと水平の角度 |
| リリース角 | 手を離れた直後の角度 |
| 最高点の高さ | リングからの高さ（m） |
| 通過位置 | リングの高さでボールの中心が通った位置。手前の縁から何cmか（手前／まんなか／奥の3区分も） |
| 打った距離 | リングの真下から、ボールを放した位置までの横の距離（m） |
| 飛んでいた時間 | 放してからリングの高さまで（秒） |
| 測れた度合い | 軌道を何コマ拾えたか。少なければ「はかれなかった」 |
| 動画ファイル名 | 動画を消した後は空にする |

- 長さの基準はリングの大きさ（内径）。位置合わせで決めたリングの左右の端から、画面の何画素が何cmかを出す
- 【推論】放物線を当てはめるので、コマの間のボールの位置も計算で補える。そのため、カメラが30fps前後でも入射角は出せる見込み

## 8. 声
- 1本ごとに「入射角」と「通過位置（てまえ／まんなか／おく）」を読み上げる
- 【提案】最初はiPadに入っている読み上げ機能（Safariの音声合成）を使う。声を変えたくなったら、ドリバトで使っているVOICEVOXの声を後で入れる

## 9. 保存と書き出し
- 数字も動画もiPadの中（Safariの保存領域）に保存する。サーバーには送らない
- 動画は1本ごと：ボールを放す約3秒前〜リングを通過して約1.5秒後。軌道の線を重ねた形で保存する
- 書き出し：数字はCSV（Excelで開ける）、全期間または期間を選んで。iPadの共有メニューでPCへ送る。動画も必要なときだけ1本ずつ、または回ごとに書き出せる
- 【仮説】Safariは、しばらく開かないサイトの保存データを自動で消すことがある。前提として、ホーム画面に追加して使う。あわせて、書き出していないデータがたまったら知らせる

## 10. 解析の中身（作る人向けの方針）
- カメラ固定・背景が空なので、まずは色と動き（前後のコマとの差）でボールを探す。重いAIモデルは使わない
- リングの自動検出に失敗しても、タップの位置合わせで必ず進めるようにする
- 1本の区切り：ボールがリングより上に上がり、リング付近を通って落ちたら1本
- 入った／外れた：ボールがリングの内側を上から下へ通ったか、とリングの下（ネット付近）に現れたか
- 解析の部品は、動画ファイルを読み込んでも動くように作る（PCで練習動画を流して精度を詰める）

## 11. 進め方
| 段階 | 中身 | 終わりの目安 |
|---|---|---|
| 0 | iPadのSafariで、カメラが何コマ撮れるか・動画を保存できるか・データが残るかを測る小さな試作 | 数字が出る |
| 1 | 解析部品を練習動画（PC）で作る | 手で数えた本数の9割以上を拾い、入った外れたが手作業の判定と合う |
| 2 | iPadのその場解析・声・画面・1本ごとの動画保存 | 自宅前のゴールで20本打って、その場で全部に数字が出る |
| 3 | 記録の一覧・手直し・CSV書き出し・動画の削除 | CSVをPCで開ける。動画を消しても数字が残る |
